# Capture / curation contract (shared Warehouse revision)

**Revision boundary:** The approved shared-Warehouse direction and requested optional app-managed Curator supersede the earlier external-agent-only restriction. Knowledge Hub is still not a general-purpose AI harness. The external-agent route remains first-class; its client owns its own provider/model, connectors and credentials. The separate app-managed route requires one explicit connection/model, secure human authentication, disclosure consent, verified bounded execution and human enablement. Local document extraction is not AI curation. See [agent bootstrap contract v1](agent-bootstrap.md) and the MCP JSON resource `knowledgehub://setup` for setup, actual runtime availability and human-only boundaries; the six requested connection targets are not a claim that every adapter works.

**Project-free MCP:** No tool requires project selection or creation. Existing tool names resolve the shared internal namespace lazily. Optional deprecated `project_id` arguments never choose a partition or grant access; `project_create` is not exposed and `project_list` is deprecated. Migration must revoke old scoped capture grants rather than silently broaden them. New shared capture access is human-only. Stable IDs, JSON-character-bounded knowledge retrieval, measured Library/capture projections, claim idempotency and human-only approval remain unchanged. Setup tools only read the guide/redacted status/catalog or stage a validated non-secret connection/model; they cannot authenticate, enable themselves, grant access or accept proposals.

The scoped Python services and `/api/projects/...` routes documented below are **historical/internal service references**, not the current public project-free API. Legacy project HTTP routes return `410 project_routes_removed`; use the shared HTTP adapter and MCP-discovered schemas. This section preserves the source-slice/submission/claim limits, not permission to create new partitions. The shared HTTP capture routes live under `/api/captures`, with human access configuration under `/api/agent/access`.

Parent registers `knowledge_hub.intake_http.register(app, store)`. Existing authentication middleware sets `request.state.human`. Parent wraps the Python services below as MCP tools; do not auto-register or launch an external client.

## Two intake routes

1. Human pastes text/uploads files in the app. Local transient capture enters `pending_agent`. Human explicitly enables a connected agent's project capture access. That agent explicitly lists/reads bounded source slices, optionally retrieves an attachment by ID, claims the snapshot/revision and submits its curated result. Submission creates a **pending** Warehouse proposal and persisted typed library suggestions, never approval. Human reviews and accepts/rejects canonical changes.
2. The user's agent already knows what truth to feed: submit evidence-backed proposals through existing `Store.propose(project_id, Proposal)` (existing Warehouse change HTTP/MCP adapter). No raw capture or fake AI pass is required. Normal revision, evidence and human-review rules still apply.

## Stable HTTP capture routes / exact payloads

- `POST /api/projects/{project_id}/captures` (human): `{"text":"optional paste","intent":"optional request","files":[{"name":"folder/relative.txt","media_type":"text/plain","content_base64":"..."}],"retention_days":7}`. Text <=100,000 chars, intent <=4,000; <=20 files; <=5 MiB decoded/file, <=20 MiB decoded/whole capture; <=29 MiB JSON body. Retention 1–30 days. Names <=240 chars; reject absolute paths, backslashes, colon, empty/dot/dot-dot segments and controls. Names are labels only; files stored by random IDs. No server paths, symlink walks or implicit private-directory reads. Empty capture rejected.
- `GET /api/projects/{project_id}/captures` (human): `{ "captures":[metadata] }`. `GET .../captures/{capture_id}` (human): local bounded inspection, original input text and extracted text/file, no attachment bytes.
- `DELETE .../captures/{capture_id}` (human): delete raw originals, capture and local suggestions. `POST .../captures/{capture_id}/finish` (human): `{"retain_source":false}` deletes raw work after review/discard; true deliberately retains until expiry. Parent must call finish after parent-owned Warehouse/library review routes. Canonical proposals survive capture deletion. Expiry is enforced at service startup and access; closed apps cannot erase files. Deletion does not secure-erase backups.
- **Historical scoped access route:** `GET /api/projects/{project_id}/captures/access` and `PUT` same path (human): `{"agent_access":true}`. The current shared adapter replaces this route; only a human may grant shared capture access. Enabling is a local handoff permission, **not** a promise about an external harness. Disable blocks subsequent agent list/read/claim/submit. Optional managed-Curator setup is separate from capture access and never permits agent self-enablement.
- `GET .../captures/{capture_id}` also exposes persisted `result` for human proposal/suggestion inspection; no separate queue-result endpoint and no automatic model execution.

Capture fields: `id`, `project_id`, `text`, `intent`, `files`, `snapshot_sha256`, `expires_at`, `status` (`pending_agent` or `proposed`), optional `claim`, optional `result`. Metadata listings omit source text/intent, extracted text, original bytes and claim tokens. Each file has `id,name,media_type,size,sha256,status,text`, optional `reason,width,height`. File status `extracted`, `image` (not OCR), or `unprocessed`. Claim is a short-lived concurrency lease, not an approval credential.

## Python services for parent MCP wrapping

`Intake(store).create/get/list/delete` are local human application services. **Do not expose unbounded human `get` directly as an MCP tool.** Use these explicit agent services on `Curator(store)`:

- `set_agent_access(project_id, enabled: bool)` / `agent_access(project_id)` — setting mutation must be wrapped human-only, never callable by an agent.
- `capture_list(project_id, limit=20, offset=0)` => `{captures:[metadata], total, next_offset}`; limit 1–100, offset >=0. Explicit human-enabled project access required.
- `capture_get(project_id,capture_id,source_id="paste",offset=0,max_chars=12000,attachment_id=None,byte_offset=0,max_bytes=1048576)` => metadata, `source_id,text,offset,next_offset` and file metadata only. Text slice max 20,000 chars, selected source `paste` or a file ID; never all extracted text unsolicited. With explicit `attachment_id`, return only that original attachment's base64 byte slice, offset, next byte offset and total/hash; max 1 MiB raw/chunk. All source/model text remains untrusted inert data. The external harness decides supported modalities/OCR; the app never claims to have read images from their names.
- `claim(project_id,capture_id,claimant,snapshot_sha256,base_revision,ttl_seconds=300)` => `{claim_token,expires_at,base_revision}`. Claimant <=100 chars, TTL 30–900 sec. Must match inspected snapshot and current project revision. Another live claim conflicts; expired lease may be reclaimed. Leases persist locally across service instances. A reentrant per-data-root OS advisory lock serializes compound capture/access operations across the desktop HTTP process and independent MCP stdio processes; lock scope includes read-back. Lock release on process death and recovery of an exact authorized submission are tested; this is local filesystem coordination, not distributed synchronization.
- `curation_submit(project_id,capture_id,submission)` where strict `CurationSubmission` is:
```json
{"snapshot_sha256":"64 lowercase hex","claim_token":"claim token","base_revision":0,"summary":"agent's reviewed draft summary","operations":[{"op":"upsert","title":"Fact","body":"Evidence-backed content","kind":"fact","evidence":[{"kind":"document","locator":"source locator","label":"Source"}],"depends_on":[]}],"library_suggestions":[{"book_title":"Guide","page_title":"Topic","body":"Suggested page"}]}
```
Existing Warehouse `Upsert` fields/UUID references are validated; <=20 operations, <=99 supplied evidence entries/operation (one local capture citation added), <=20 library suggestions, <=20,000 chars/suggestion body. Submission requires live matching claim token, capture snapshot and project revision. Returns `{warehouse_change:{status:"pending",...},library_suggestions:[...]}` and persists it on the capture with `status:"proposed"`. Exact repeat may read the same result; changed repeat conflicts. No canonical approval, shell, SQL, provider call or harness execution occurs.

Parent may expose MCP names `capture_list`, `capture_get`, `capture_claim`, `curation_submit` using these services. Agent Bearer must never call human access enablement, settings, approval or source deletion. HTTP agent endpoints are intentionally not added; parent MCP is the integration surface.

## Extraction and privacy limits

Local UTF-8 plain text/Markdown/CSV/JSON; PDF text; DOCX paragraphs/tables; PNG/JPEG/WebP validation. Unsupported/corrupt/encrypted/scanned-without-text files remain local with explicit reasons. No embedded-image OCR or macro execution. PDF/DOCX use fixed local extraction-worker commands (not harness commands), empty environment, 4s CPU / 6s wall per file; PDF <=100 pages, decoded page content <=2 MiB, filter output <=4 MiB; DOCX <=1,000 ZIP entries, <=20 MiB expanded; extracted text <=100,000 chars/file. Images single-frame <=20 MP. No hard macOS memory-cap claim (OS rejects RLIMIT_AS); parsing is not an OS sandbox.

**Frozen build hook implemented:** CLI dispatches `--capture-extractor-worker MEDIA_TYPE` to `knowledge_hub.intake_extractors.worker_main(MEDIA_TYPE)` before normal startup. Genuine 0.2.0 bundle invocation verified DOCX text extraction and PDF worker handling. Source runtime continues to use `python -m knowledge_hub.intake_extractors --worker MEDIA_TYPE`. This is document parsing, not model execution or a general command runner.

All canonical data, originals and proposals are local. Human-enabled external-agent access is explicit disclosure/handoff: independent clients may use cloud models, and this app cannot control a harness after it reads. That client owns downstream-provider routing/retention controls; there is no blanket no-training guarantee. Optional app-managed inference needs separate human-confirmed destination/model, disclosure consent and enablement; only app-owned credentials use the OS credential store. Official CLI credentials remain with that CLI and must never be extracted/copied/replayed. No secrets belong in knowledge or MCP responses. Original attachment retrieval includes embedded metadata; no EXIF/location scrubbing guarantee. No conversation archive or unconsented automatic egress.

## Revision history / verification scope

Earlier provider prototypes are not evidence of the new connection adapters' readiness. Keep real local extraction, capture storage, validation and queue/review tests. Setup contract verification uses initialized real SDK subprocesses on isolated synthetic roots, redacted state/readback and extra-argument/authority refusal checks. No live/private provider calls, owner-data diagnostics, commits or pushes are part of that verification.
